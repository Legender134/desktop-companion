# 给桌面灵伴添加新宠物

新版宠物包不再要求固定 11 行图集。本指南主体介绍最常用的 v3：你只需准备一张透明 WebP 和一个 JSON；待机、左右普通移动和一个互动动作是最低要求，其余动作可以不做，也可以继续增加。

精确字段见 [v3 动态宠物包规范](pet-pack-format-v3.md)和 [JSON Schema](../schemas/pet-pack-v3.schema.json)。已经制作好的旧式图集仍可查看 [v2 兼容规范](pet-pack-format-v2.md)。需要多图集分层、宽特效或形态切换时，改用 [v4 分层多形态规范](pet-pack-format-v4.md)和 [v4 JSON Schema](../schemas/pet-pack-v4.schema.json)。

## 先选择 v2、v3 还是 v4

- **v2**：已有固定 8 列 × 11 行、每格 `192 × 208` 的旧图集，希望原样兼容。新素材通常不选 v2。
- **v3**：单一形态、单张图集，动作数量和帧数需要动态扩展。这是普通新宠物的首选，继续按本指南操作。
- **v4**：需要 1–8 张不同格尺寸的图集、身体与宽特效分层、full/simplified 特效质量、多个 form、transformation、sequence 或 bucket 共享冷却。请直接按 v4 规范制作，不要从 v3 只修改版本号。

v4 的 ID 和所有技术键采用 lower camelCase，只允许首字母小写的英文字母加后续英文字母/数字；`snow_cat` 在 v3 合法，但在 v4 应改为 `snowCat`。目录名仍必须与 `id` 完全相同。

## 一、复制模板

1. 复制 [`examples/pet-pack-template`](../examples/pet-pack-template) 文件夹。
2. 把文件夹改成英文 ID，例如 `snow_cat`。
3. 把 `pet.json` 中的 `id` 同样改成 `snow_cat`。
4. 修改 `displayName`、说明和动作名称。

ID 只能使用小写英文字母、数字、下划线和连字符，首字符必须是字母或数字；中文名称写在 `displayName` 中。

## 二、制作图集

- 每一格固定 `192 × 208` 像素，背景透明。
- 整图可以有任意合理的行列数，但宽必须是 192 的整数倍，高必须是 208 的整数倍。
- 最简单的排法是“一行一个直接绘制的动作”，图集宽度按帧数最多的动作决定。
- 在 JSON 中用 `row`、`startColumn` 和 `frameCount` 告诉程序每个动作在哪里。
- 左右完全对称时可使用 `mirrorOf`，这样不需要重复占用一行；不对称角色建议分别绘制。

模板默认需要4个直接绘制行：待机、向右普通移动、互动和向右遁光；向左动作由程序镜像。模板最大帧数是8，因此示例图集尺寸为 `1536 × 832`。如果删掉遁光，图集可以继续变矮；如果某个动作需要12帧，图集宽度相应改为 `2304`。

## 三、填写基础动作

每个宠物必须具备：

- 一个 `role: "idle"` 的循环待机；
- `direction: "left"` 和 `"right"` 的普通 `role: "move"`；
- 至少一个 `role: "interaction"` 的回应动作。

跳跃、睡觉、施法、观察和更多待机都写成不同 ID 的 `interaction`。它们会自动出现在动作菜单中；设置 `showInMenu: false` 可隐藏。

`frameCount` 可以按动作分别设置，普通动作允许1–512帧；看向鼠标的 `gaze` 仍只能使用16、32或64帧。统一速度使用 `frameMs`；某些帧需要特殊停顿时，用与帧数等长的 `frameDurations` 数组替代。即使使用长动作，整个图集仍不能超过2048格、5000万像素和32 MiB，JSON不能超过64 KiB。

### 只供手动观看的动作

较长的完整展示、剧情动作或彩蛋如果不适合自动出现，可以写成：

```json
{
  "label": "完整动作展示",
  "role": "interaction",
  "row": 8,
  "startColumn": 0,
  "frameCount": 8,
  "frameDurations": [120, 160, 180, 240, 240, 180, 160, 120],
  "repeatCount": 1,
  "autoplayWeight": 0,
  "showInMenu": true,
  "includeInShowcase": false
}
```

`showInMenu: true` 让用户能从右键菜单单独播放；`autoplayWeight: 0` 排除“随机动作”和“自主小动作”；`includeInShowcase: false` 再把它从通用“动作展示”中排除。三个字段作用不同，需要同时填写。

## 四、避免同类特效连续播放

如果宠物包含多套施法、爆发或强光动作，建议给它们设置相同的自动播放组：

```json
"autoplayGroup": "spell"
```

随机播放一套 `spell` 后，下一次会优先选择没有该组名的日常动作，避免两套不同术法连续闪光。只给需要互斥的 `interaction` 填写；普通待机、移动和日常动作可以省略。

## 五、可选的快速移动

遁光、瞬移和冲刺使用 `role: "burstMove"`。推荐设置：

```json
{
  "label": "遁光向右",
  "role": "burstMove",
  "direction": "right",
  "row": 3,
  "frameCount": 8,
  "frameMs": 90,
  "travelStartFrame": 3,
  "travelEndFrame": 6,
  "autoplayWeight": 1,
  "cooldownMs": 45000,
  "minDistance": 280,
  "travelDistanceRatio": 0.5,
  "maxVerticalRatio": 0.1
}
```

普通移动设为权重19、遁光设为权重1时，符合距离和冷却条件的闲逛约有5%使用遁光。`travelDistanceRatio: 0.5` 表示移动当前屏幕可移动宽度的一半；程序会选择空间足够的一侧并保证宠物不出屏。人物光化前停在起点，飞行阶段快速跨越，显形阶段停在终点。

## 六、安装和检查

1. 把 `pet.json` 和 `spritesheet.webp` 放在同一个宠物文件夹。
2. 启动桌面灵伴，右键选择“打开宠物目录”。
3. 把完整文件夹复制进去。
4. 选择“重新扫描宠物”。
5. 从“切换宠物”中选择新角色，再运行“动作展示”检查互动动作。

如果宠物没有出现，依次检查：目录名是否等于 ID、JSON 是否为 UTF-8、图集是否带透明通道、宽高是否为单格整数倍、动作引用的格子是否有内容，以及左右移动和互动能力是否齐全。错误详情记录在 `%LOCALAPPDATA%\DesktopCompanion\DesktopCompanion.log`。

宠物包只应包含图集和 JSON。不要放入 Python、JavaScript、DLL 或 EXE；程序也不会执行这些文件。

### 仓库内验证命令

v4 清单先用 Draft 2020-12 Schema 验证（把最后一个参数替换成自己的 `pet.json`）：

```powershell
& .\.venv\Scripts\python.exe -c "import json,sys; from jsonschema import Draft202012Validator as V; s=json.load(open(sys.argv[1],encoding='utf-8')); m=json.load(open(sys.argv[2],encoding='utf-8')); V.check_schema(s); V(s).validate(m)" schemas\pet-pack-v4.schema.json tests\fixtures\pets\multiformV4\pet.json
```

再运行真实注册表、图集解码和组合测试：

```powershell
& .\.venv\Scripts\python.exe -m pytest tests\test_pet_pack_v4_fixture.py tests\test_pet_registry.py tests\test_animation_catalog.py -q
```

上面的 pytest 命令只验证仓库自带 fixture，不会自动读取制作者自己的 v4 包。自己的 v4 包必须把前一条 schema 命令的最后一个参数替换成自己的 `pet.json` 路径；Schema 通过不代表 WebP 和跨引用一定正确，最终仍必须让桌面灵伴“重新扫描宠物”，实际切换 full/simplified 并检查日志中没有该包的隔离错误。
