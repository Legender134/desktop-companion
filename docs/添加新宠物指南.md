# 给桌面灵伴添加新宠物

这份指南面向第一次制作宠物包的人。你不需要修改桌面灵伴源码，但需要准备符合固定布局的透明动画图集。已经熟悉格式的制作者可直接查看 [v2 宠物包技术规范](pet-pack-format-v2.md)和 [JSON Schema](../schemas/pet-pack-v2.schema.json)。

## 一、先理解宠物包是什么

一个宠物包就是一个文件夹，里面必须有两个文件：

```text
my_pet\
├─ pet.json
└─ spritesheet.webp
```

- `spritesheet.webp` 保存所有动作帧；
- `pet.json` 告诉程序宠物叫什么、动作叫什么、哪些动作更常随机出现；
- 文件夹名称必须与 `pet.json` 的 `id` 完全一致。

桌面灵伴只读取这两个数据文件，不会执行宠物包里的 Python、JavaScript、EXE 或 DLL。

## 二、最快的制作方法

1. 复制仓库中的 [`examples/pet-pack-template`](../examples/pet-pack-template) 文件夹。
2. 把复制后的文件夹改成自己的宠物 ID，例如 `snow_cat`。
3. 修改里面的 `pet.json`，并把 `id` 同样改成 `snow_cat`。
4. 按本指南的图集布局制作 `spritesheet.webp`。
5. 把完整的 `snow_cat` 文件夹复制到桌面灵伴的用户宠物目录。
6. 右键宠物，选择“重新扫描宠物”，再到“切换宠物”里选择它。

不能只放一个 WebP 文件。每个宠物都必须同时有图集和 JSON。

## 三、怎样选择宠物 ID？

`id` 是程序内部使用的唯一名字，也就是文件夹名。它必须满足：

- 长度 1–64 个字符；
- 只能使用小写英文字母 `a-z`、数字 `0-9`、下划线 `_` 和连字符 `-`；
- 第一个字符必须是字母或数字；
- 不能使用已被占用的 `shiyi` 或 `ziling`；
- 文件夹名和 JSON 中的 `id` 必须逐字相同。

正确示例：`snow_cat`、`fox-01`、`momo2`

错误示例：`SnowCat`、`雪猫`、`my pet`、`_cat`

显示给用户看的中文名字写在 `displayName`，不需要放进 ID。

## 四、图集必须是什么样？

`spritesheet.webp` 必须满足以下固定规格：

| 项目 | 固定值 |
|---|---|
| 文件格式 | 带透明通道的 WebP |
| 整图尺寸 | `1536 × 2288` 像素 |
| 网格 | 8 列 × 11 行 |
| 每格尺寸 | `192 × 208` 像素 |
| 最大文件大小 | 32 MiB |

图集坐标从左上角开始，第一行和第一列都按 `0` 计数。每一格的位置是：

```text
左边界 = 列号 × 192
上边界 = 行号 × 208
```

### 动作行布局

| 行号 | 固定动作槽位 | 必须有内容的列 | 其余列 |
|---:|---|---|---|
| 0 | `idle` 待机 | 0–6，共 7 格 | 第 7 列完全透明 |
| 1 | `moveRight` 向右移动 | 0–7，共 8 格 | 无 |
| 2 | `moveLeft` 向左移动 | 0–7，共 8 格 | 无 |
| 3 | `greet` 问候动作 | 0–3，共 4 格 | 第 4–7 列完全透明 |
| 4 | `jump` 跳跃或同位置动态动作 | 0–4，共 5 格 | 第 5–7 列完全透明 |
| 5 | `special` 角色特色动作 | 0–7，共 8 格 | 无 |
| 6 | `wait` 等待动作 | 0–5，共 6 格 | 第 6–7 列完全透明 |
| 7 | `observe` 观察动作 | 0–5，共 6 格 | 第 6–7 列完全透明 |
| 8 | `curious` 好奇或思考动作 | 0–5，共 6 格 | 第 6–7 列完全透明 |
| 9 | 看向方向 0°–157.5° | 0–7，共 8 格 | 无 |
| 10 | 看向方向 180°–337.5° | 0–7，共 8 格 | 无 |

每个“必须有内容”的格子至少要有一个不透明像素；表中要求透明的格子必须完全透明，否则程序会拒绝宠物包。

### 看向鼠标的 16 个方向

方向从正上方开始，按顺时针每格增加 22.5°：

```text
第 9 行：0°、22.5°、45°、67.5°、90°、112.5°、135°、157.5°
第 10 行：180°、202.5°、225°、247.5°、270°、292.5°、315°、337.5°
```

其中 0° 是上，90° 是右，180° 是下，270° 是左。即使不准备使用“看向鼠标”，当前 v2 格式仍要求这 16 格都存在。

### 绘制建议

- 每帧都使用透明背景，不要填白色或黑色底；
- 尽量让角色脚底或身体中心在各帧中保持相近位置，减少播放时抖动；
- 向右和向左移动应分别画在第 1、2 行，不要只依赖程序镜像；
- 不要改变整图尺寸或每格尺寸；
- 导出后再次确认透明空格没有残留肉眼难见的半透明像素。

## 五、怎样填写 pet.json？

可以直接复制下面的内容，再修改 ID、名称、说明和动作显示名称：

```json
{
  "id": "my_pet",
  "displayName": "我的宠物",
  "description": "这是我的第一个桌面灵伴宠物包。",
  "spriteVersionNumber": 2,
  "spritesheetPath": "spritesheet.webp",
  "iconFrame": {"row": 0, "column": 0},
  "actions": {
    "idle": {"label": "安静陪伴", "autoplayWeight": 0},
    "moveRight": {"label": "向右移动", "autoplayWeight": 0},
    "moveLeft": {"label": "向左移动", "autoplayWeight": 0},
    "greet": {"label": "打个招呼", "autoplayWeight": 3},
    "jump": {"label": "开心跃起", "autoplayWeight": 1},
    "special": {"label": "特别动作", "autoplayWeight": 2},
    "wait": {"label": "安静等待", "autoplayWeight": 3},
    "observe": {"label": "看看四周", "autoplayWeight": 2},
    "curious": {"label": "好奇观察", "autoplayWeight": 3}
  }
}
```

保存时使用 UTF-8 编码。JSON 必须使用英文双引号，不能加入注释，也不能在最后一项后面留下多余逗号。

### 顶层字段

| 字段 | 能否修改 | 规则 |
|---|---|---|
| `id` | 必须修改 | 与文件夹名相同，遵守 ID 规则 |
| `displayName` | 可以修改 | 菜单里显示的名字，去除首尾空格后 1–64 字符 |
| `description` | 可以修改 | 可省略，最多 500 字符 |
| `spriteVersionNumber` | 不能修改 | 必须是数字 `2` |
| `spritesheetPath` | 不能修改 | 必须精确写成 `spritesheet.webp` |
| `iconFrame` | 可以修改 | 托盘图标使用的可见帧，行 0–10、列 0–7 |
| `actions` | 可以改值，不能改键 | 9 个固定动作槽位必须全部存在 |

`iconFrame` 通常使用 `{"row": 0, "column": 0}`。它必须指向图集中实际有内容的格子。

## 六、动作名称和自动权重怎么设置？

`idle`、`moveRight` 等英文键是程序与图集之间的固定协议，不能翻译、删除或改名。可以修改的是 `label` 和 `autoplayWeight`。

| 键 | 对应图集行 | `autoplayWeight` 规则 |
|---|---:|---|
| `idle` | 0 | 必须为 0 |
| `moveRight` | 1 | 必须为 0 |
| `moveLeft` | 2 | 必须为 0 |
| `greet` | 3 | 0–10 |
| `jump` | 4 | 0–10 |
| `special` | 5 | 0–10 |
| `wait` | 6 | 0–10 |
| `observe` | 7 | 0–10 |
| `curious` | 8 | 0–10 |

- `label` 是菜单显示名称，去除首尾空格后必须是 1–32 个可打印字符；
- 权重越大，单击宠物、数字 `0`、中键随机和自主小动作越容易选中它；
- 权重为 0 表示不会被随机选中，但仍可从菜单或数字快捷键手动播放；
- 六个原地动作中至少一个权重大于 0；
- 待机和左右移动权重必须为 0，避免自主动作改变宠物位置；
- 同一个随机动作不会连续播放两次。

例如权重分别为 1、3、6 时，三者大致占总随机机会的 10%、30%、60%，但程序还会避免立即重复，所以实际连续结果会略有不同。

## 七、怎样安装自己做的宠物？

最简单的方法：

1. 启动桌面灵伴。
2. 右键宠物或托盘图标。
3. 点击“打开宠物目录”。
4. 把整个 `my_pet` 文件夹复制进去。
5. 返回桌面灵伴，右键选择“重新扫描宠物”。
6. 打开“切换宠物”，点击自己的宠物名称。

最终目录应类似：

```text
%APPDATA%\DesktopCompanion\pets\my_pet\pet.json
%APPDATA%\DesktopCompanion\pets\my_pet\spritesheet.webp
```

不要把 `pet.json` 和图集直接散放在 `pets` 根目录；每只宠物都必须独占一个子文件夹。

## 八、发布前检查清单

- [ ] 文件夹名与 `pet.json` 的 `id` 完全一致；
- [ ] 文件名正好是 `pet.json` 和 `spritesheet.webp`；
- [ ] JSON 使用 UTF-8、英文双引号、没有注释和尾随逗号；
- [ ] `spriteVersionNumber` 是数字 2；
- [ ] 图集是 1536 × 2288、带透明通道的 WebP；
- [ ] 每格是 192 × 208，动作行没有放错；
- [ ] 有效格都有可见像素，未使用格完全透明；
- [ ] `actions` 的 9 个英文键完整且没有额外键；
- [ ] 三个位移动作权重为 0，至少一个原地动作权重大于 0；
- [ ] `iconFrame` 指向可见格；
- [ ] 在桌面灵伴中重新扫描、切换并播放“动作展示”检查过完整效果。

## 九、新宠物没有出现时怎么排错

重新扫描后，程序会忽略不合格的宠物包，不会让整个应用崩溃。按下面顺序检查：

1. 文件夹位置是否正确；
2. 文件夹名与 `id` 是否一致；
3. 两个文件名是否完全正确；
4. JSON 是否能正常解析；
5. 图集尺寸和透明通道是否正确；
6. 所有有效格和透明空格是否符合表格；
7. `actions` 是否缺键、多键或权重越界；
8. `shiyi`、`ziling` 是否被误用为自制宠物 ID。

详细错误会写入：

```text
%LOCALAPPDATA%\DesktopCompanion\logs\DesktopCompanion.log
```

可以用记事本打开日志，搜索 `Ignoring invalid pet pack`，后面会说明失败原因。

## 十、兼容和安全边界

- `pet.json` 最大 64 KiB；
- `spritesheet.webp` 必须大于 0 且不超过 32 MiB；
- 宠物文件夹和两个数据文件不能是符号链接或目录联接；
- 不接受绝对路径、`..` 路径或自定义图集文件名；
- 完全省略 `actions` 可兼容 2.1 宠物包，但新包应填写完整动作信息；
- 覆盖升级会保留用户宠物，卸载会删除用户宠物目录，卸载前请备份。

分享宠物包前，请确认自己拥有角色图像、动画和名称的使用及再分发权限。非商用或学习用途不自动等于获得素材授权。
