# 南宫婉“月下屋檐”制作过程视频设计

日期：2026-07-22

状态：用户已确认叙事方向、素材顺序与首稿无配音策略，等待书面设计复核

## 1. 目标

制作一支约4分40秒、1920×1080、16:9的横屏制作记录母版，展示南宫婉“月下屋檐”从站立吃栗子动作逐步发展为166帧常驻状态的思路变化。横屏母版确认后，再从同一工程剪出60–90秒、9:16的竖屏版本。

视频的重点是“想法为什么变化”和“每个重要阶段的完整产品”，不是展示明显制作事故。人物下半身整块固定、多出手臂、严重位置错乱等画面一律不进入公开成片。

## 2. 受众与语气

- 主要平台：B站横屏；后续派生抖音竖屏。
- 叙事语气：真实、日常、带克制幽默，不采用官方宣传片口吻。
- 旁白方向：沉稳、冷静、略带回顾试错时的无奈感；只借鉴“韩立式人物气质”，不得声称或模仿动漫原配音。
- 所有正式版本必须提示旁白由AI生成。
- 首次审片版暂不生成语音，以字幕和预留旁白时间槽完成剪辑。当前电脑未配置 `OPENAI_API_KEY`，该限制不得用其他未经确认的临时声线绕过。

## 3. 总体叙事结构

采用“时间线＋问题章节”，但只保留六个完整、可观看的阶段：

| 时间 | 阶段 | 核心作用 |
|---|---|---|
| 00:00–00:18 | 站立吃栗子 | 作为故事起点：有角色习惯，但缺少月下屋檐的标志性画面 |
| 00:18–00:58 | 36帧影视分镜版 | 展示首次还原名场面的思路，以及“更像独立动画片段”的局限 |
| 00:58–01:38 | 48帧原地展开版 | 展示从影视分镜转向桌面空间连续动作，但坐下后立即起身仍不自然 |
| 01:38–02:18 | 第一版屋檐常驻状态 | 展示核心转折：从一次性动作变为能够停留的状态 |
| 02:18–03:45 | V9小圆月166帧版 | 完整展示进入、九种随机常驻动作和退出 |
| 03:45–04:40 | 三种新月亮背景 | 使用相同的御物吃栗动作，只比较背景构图 |

六段必须按上述顺序出现，不在开头额外插播最终V9钩子，避免破坏用户指定的演化顺序。

## 4. 各阶段画面

### 4.1 站立吃栗子

- 使用10帧、2080毫秒的 `tasteCake` 动作。
- 至少完整播放一次。
- 用字幕提出起始问题：它能表达喜欢吃栗子，但尚未形成月下屋檐的角色记忆点。
- 不把它描述为失败品；结尾说明该动作仍可作为独立低频彩蛋。

### 4.2 36帧影视分镜版

- 从历史图集和匹配配置生成9100毫秒MP4。
- 完整播放一次远景、推近、手部和嘴部特写。
- 只说明它与桌面宠物本体存在镜头割裂，不展示其制作过程中的粗糙中间帧。

### 4.3 48帧原地展开版

- 使用现有9600毫秒MP4，完整播放一次。
- 说明它解决了人物比例和桌面位置连续性，但“为了吃栗子坐下、随后马上站起”的行为逻辑仍显刻意。

### 4.4 第一版屋檐常驻状态

- 使用 `moonlit-rooftop-all-actions.mp4`。
- 截取约12秒，必须让观众看出南宫婉会留在屋檐上继续活动。
- 不展示后续严重锚点错误或下半身固定问题。

### 4.5 V9小圆月166帧版

- 使用 `moonlit-rooftop-transparent-v9.mp4`，按原时序完整展示全部动作。
- 入口和退出使用固定文字：“进入月下屋檐”“离开屋檐”。
- 九种常驻动作逐项显示中文名称：屋檐静坐、仰望月色、月下含栗、含栗欲眠、夜风拂袖、侧眸相望、抬手拢发、轻触朱雀环、白鹤掠月。
- 屏幕必须明确提示：“进入屋檐后，这九种动作会按权重随机出现；演示视频为方便观看而依次播放。”

### 4.6 三种新月亮背景

- 依次展示：184像素完整大圆月、232像素越界巨月、月面完全覆盖背景。
- 每种背景只播放同一套8990毫秒 `rooftopChestnut` 御物吃栗动作。
- 三段动作、时长、人物位置和屋檐必须完全一致，只允许背景变化。
- 每段只标注方案名称，不提前评价优劣；最后邀请观众选择。
- 小圆月已经在V9完整段落中展示，不在此处重复播放。

## 5. 真实聊天内容

- 只在概念转折处出现少量真实聊天文字，不连续滚动聊天记录。
- 可使用的核心意思包括：“这更像在看动画”“坐下吃完马上起来不自然”“既然是一种状态，中间动作也应随机”。
- 不展示私人令牌、账户页面、本机用户名、绝对文件路径或其他无关对话。
- 不展示带有人物结构错误的截图，即使对应聊天原话具有幽默效果。
- 如真实截图无法干净裁切，则改用统一样式重排文字，并标注“制作时的真实反馈”。

## 6. 文字与视觉风格

- 背景使用桌面环境，并保留任务栏或桌面图标，让观众明确这是桌面宠物。
- 人物保持画面视觉中心，不能因说明文字被挤到角落。
- 阶段标题使用简短中文，不使用大段技术说明覆盖人物。
- 旁白字幕位于安全区底部；动作名位于左上或右上，避开人物头部、栗子和月亮主体。
- 字体、颜色和转场保持朴素，避免科技感、发布会感和夸张粒子转场。
- 版本之间使用直接切换或短淡化；概念变化靠旁白字幕解释，不靠故障特效嘲讽旧版。

## 7. 音频策略

### 首次审片版

- 不含最终AI旁白。
- 使用完整旁白字幕和正确停留时长，为后续配音保留空间。
- 暂不加入来源不明的背景音乐；允许使用安静的无音乐版本进行结构审片。

### 正式横屏版

- 在本机设置 `OPENAI_API_KEY` 后，先试听 `cedar`、`onyx`、`echo` 三种内置男声。
- 选择沉稳、克制且中文清晰的一种；不得使用“南宫婉原声”“韩立原声”等误导表述。
- 旁白音量高于背景音乐，动作本身无音效时不虚构法术音效。
- 片尾或简介注明“旁白由AI生成”。

## 8. 素材处理流程

1. 从本机历史素材库读取WebP、JSON和现有MP4，不修改归档源文件。
2. 新生成五段标准中间视频：站立吃栗子、36帧影视版、完整大圆月吃栗、越界巨月吃栗、全背景月面吃栗。
3. 所有透明动作先合成到统一桌面背景，再编码为1920×1080、H.264 MP4。
4. 现有第一版常驻和V9视频按需要裁切或重新合成，禁止改变动作实际速度。
5. 按六阶段时间线组合，加入阶段名、动作名、旁白字幕和真实反馈节点。
6. 导出审片版MP4与逐段时间清单；不覆盖任何历史预览。

## 9. 输出

首稿输出到Git忽略的本机工作目录，不进入安装包或仓库：

```text
work/nangongwan-rooftop-making-of-video/
  master-v1-no-voice-1920x1080.mp4
  master-v1-timeline.json
  intermediates/
  review-frames/
```

正式横屏版确认后再输出带旁白母版；竖屏版另行设计人物缩放、字幕安全区和画面裁切，不直接机械裁掉横屏两侧。

## 10. 异常处理与验证

- WebP帧数、JSON时长或动作坐标不匹配时停止生成对应中间视频，不猜测帧序。
- 任一月亮比较段出现人物、动作时长或位置差异时重新生成，保证公平对比。
- 导出前扫描全部聊天截图，确认不存在令牌、账户、用户名和路径。
- 检查公开视频没有引用 `07-private-anime-reference-DO-NOT-PUBLISH/` 中的动漫原片。
- 使用 `ffprobe` 核对分辨率、帧率、编码、总时长和音轨状态。
- 抽取每个章节首尾帧，检查文字安全区、桌面任务栏、人物居中和转场连续性。
- 完整观看审片版一次，确认没有严重失误画面、重复长镜头或无法读完的字幕。

## 11. 首稿通过标准

- 六个阶段顺序与用户指定完全一致。
- 36帧和48帧版本均完整播放一次。
- 第一版常驻只展示概念成立的画面。
- V9完整展示入口、九种随机常驻动作和退出，并正确解释真实运行时是随机播放。
- 三种新月亮背景只播放同一套御物吃栗动作。
- 不出现下半身整块固定、多手、明显位置错乱等严重制作事故。
- 不使用动漫参考视频、不泄露私人信息、不修改安装包或历史素材库。
- 即使没有旁白，观众也能仅靠画面与字幕理解整体演化过程。
