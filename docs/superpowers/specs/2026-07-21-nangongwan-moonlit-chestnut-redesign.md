# 南宫婉“月下含栗”原地展开式重做设计

日期：2026-07-21

状态：已批准，待实施

适用范围：桌面灵伴内置宠物“南宫婉”

取代方案：`2026-07-21-nangongwan-moonlit-chestnut-design.md` 中以远景、推镜和人物特写为核心的旧画面方案

## 1. 问题

现有 2.4.1“月下含栗”虽然配置了 36 帧和约 9.1 秒时长，但运行素材实际主要由 8 张关键图配合轻微缩放生成。人物会从正常桌面站姿突然变为月下屋檐远景，再切入脸部和手部特写，最后骤然回到站姿。它更像在桌面上播放一段动画片，而不是南宫婉本人在桌面空间中完成动作。

按真实时序复核后，主要接缝的画面突变量如下：

- 第 4→5 帧：人物突然出现，约 40.65% 像素发生明显变化。
- 第 13→14 帧：远景直接切到坐姿中景，约 55.62% 像素发生明显变化。
- 第 20→21 帧：坐姿中景直接切到人物特写，约 60.98% 像素发生明显变化。
- 第 31→32 帧：脸部特写直接切回屋檐坐姿，约 63.09% 像素发生明显变化。
- 第 35→36 帧：坐姿中景直接缩回远景，约 43.20% 像素发生明显变化。

因此本轮不在旧 36 帧上继续修补，而是完整替换该动作的画面和时序。

## 2. 目标

- 南宫婉始终保持为桌面上的同一个人物，位置、大小和动作因果连续。
- 用“站立→月景显现→坐下→御物含栗→起身→月景消散”的完整身体动作表现角色，而不是播放远近景剪辑。
- 保留动画中可以明确辨认的月夜屋檐、蓝银造型、金黄色栗糕和紫色御物灵光。
- 取消远景小人和脸部/嘴部大特写，人物尺寸最多只做约 10% 的轻微变化。
- 第 1 帧和最后 1 帧均能与正常待机姿态无缝衔接。
- 新动作使用 48 帧、正常速度 9600 毫秒，继续支持右键手动播放、动作展示和约 1/20 的自主触发权重。
- 2.4.1 的旧图集必须以另一张 WebP 原样保留，并随安装包一起安装，供以后比较、恢复或设计彩蛋使用。

## 3. 非目标

- 不新增南宫婉从未表现过的法术，不把屋檐显现解释为她施法召唤建筑。
- 不修改 Codex 宠物版南宫婉。
- 不改变其他宠物和南宫婉其他动作。
- 不升级宠物包格式；现有 v3 动态动作、跨行取帧和可变帧时长已经足够。
- 不为该动作增加音效、台词、字幕或不透明矩形背景。

## 4. 核心表现原则

### 4.1 桌面空间连续性

- 动作窗口在屏幕上的位置全程不移动。
- 第 1 帧沿用正常待机的中立站姿；人物脚底基准、头部大小和身体朝向必须与待机一致。
- 月亮和屋檐围绕人物渐渐出现，不能先清空人物再替换成一幅场景。
- 人物头部视觉尺寸相对待机不得超过约 ±10%；不使用远景缩小或脸部放大镜头。
- 人物站立阶段的脚底基准允许最多 3 像素误差；坐下后屋檐承重点固定，不能在相邻帧间漂移。
- 最后阶段必须先让人物完全站稳，再消散屋檐和月光；最后一帧允许与待机首帧完全相同，这是边界衔接而不是凑帧。

### 4.2 月亮和屋檐

- 月光先以淡蓝白辉光从人物身后渐亮，再逐步显出巨大局部月面；不出现一轮小月亮突然替换人物。
- 因为取消远景，整套动作不再显示完整月轮。月亮始终是位于人物身后的局部弧面，并保持柔边透明渐隐。
- 屋檐轮廓沿人物脚边逐步显现，视觉上属于月夜场景过渡，不使用紫光、法阵或施法手势来“召唤”屋檐。
- 屋檐几何在所有帧中保持同一透视、瓦当方向和檐角位置；人物坐下时臀部真实落在最外缘，双腿自然垂向画面左侧。
- 场景边缘必须使用透明渐隐，不出现方形夜空或整块背景板。

### 4.3 人物、栗糕和灵力

- 人物使用当前蓝银造型，发饰、银色护腕、蓝色袖口和耳饰保持一致。
- 站到坐的过程中必须依次表现转髋、屈膝、手扶檐面、身体下沉和双腿越过檐边；不得用站姿和坐姿两张图直接切换。
- 右手抬起后，紫色灵光只在指间和栗糕附近形成微弱光点与细环。
- 栗糕保持金黄色、有细纹的小块造型；通过颜色、轮廓和局部辉光保证常用桌面尺寸下仍可辨认。
- 含栗阶段保持全身或四分之三身构图，只表现轻含、一次眨眼和很淡的满足神情，不做脸部大特写或夸张咀嚼。
- 起身不是简单倒放坐下：先放低右手、身体前倾、手撑屋檐、收腿并转正重心，最后双脚回到待机基准。

## 5. 48 帧分段和时序

动作正常速度总时长固定为 9600 毫秒：

| 帧 | 阶段 | 画面和运动 | 时长 |
|---|---|---|---:|
| 1–4 | 站姿衔接 | 保持待机大小与位置，停下、抬眼，发尾和袖摆轻动 | 600 ms |
| 5–10 | 月景显现 | 淡蓝月辉由弱到强，屋檐轮廓沿脚边展开，局部月面逐渐清晰 | 1050 ms |
| 11–20 | 转身坐下 | 转髋、屈膝、手扶、身体下沉、双腿越过檐边并坐稳 | 1900 ms |
| 21–25 | 月下停留 | 衣摆和头发落定，侧坐檐角，视线转向右手 | 950 ms |
| 26–33 | 御物取栗 | 右手抬起，指间聚光，栗糕沿短弧线浮到手边 | 1550 ms |
| 34–39 | 含栗回味 | 栗糕送到唇边，轻含、眨眼、短暂停留；轻微推近不超过 10% | 1250 ms |
| 40–45 | 起身还原 | 放手、前倾、手撑、收腿、起身并重新站稳 | 1550 ms |
| 46–48 | 场景消散 | 人物保持站姿，屋檐与月光依次淡出，回到待机首帧 | 750 ms |

精确逐帧时长如下，共 48 项、总和 9600 毫秒：

```json
[140, 140, 150, 170,
 150, 160, 170, 180, 190, 200,
 170, 170, 180, 180, 190, 190, 200, 200, 210, 210,
 170, 180, 190, 200, 210,
 160, 170, 180, 190, 200, 210, 220, 220,
 170, 180, 190, 210, 240, 260,
 200, 220, 240, 260, 290, 340,
 200, 250, 300]
```

## 6. 素材生产规则

- 48 个运行帧不能再由少量分镜配合整体缩放凑成。
- 至少绘制 20 个独立姿态关键帧；站到坐不少于 8 个不同身体姿态，起身不少于 6 个不同身体姿态，御物与含栗不少于 6 个不同手臂/头部姿态。
- 其余中间帧可以在相邻且结构一致的姿态间补间，但不得跨不同人物比例、屋檐透视或手臂结构直接插值。
- 允许在停留阶段使用呼吸、眨眼、发丝、袖摆、月辉和紫光变化；不允许仅靠 0.5% 左右的全图缩放制造“不同帧”。
- 关键帧源和可复现构建脚本继续保留在 `tools/assets/` 与 `tools/`，但必须替换现有 8 格分镜源和以硬切为核心的构建逻辑。

## 7. 图集和动作配置

- 在重画前，先把当前 2.4.1 `spritesheet.webp` 按字节复制为 `spritesheet-moonlit-chestnut-v2.4.1-legacy.webp`，与新版图集放在同一个南宫婉资源目录中。归档文件固定为 8,634,008 字节，SHA256 为 `990D1EE9DB3632102E9F07984301519606A9CC3591585E8EF892D0BA975A9D3E`。
- `pet.json` 的活动图集仍只指向 `spritesheet.webp`；归档 WebP 不加入菜单、随机动作、动作展示或普通资源解析，不会与新版同时加载到内存。
- PyInstaller 和 Inno Setup 必须把归档 WebP 一起复制到安装目录。用户选择保留它，因此接受冻结目录和安装包体积相应增加。
- 新构建脚本只能改写活动的 `spritesheet.webp`，不得修改、重新编码或覆盖归档 WebP。
- 动作 ID 继续使用 `moonlitChestnut`，菜单名继续使用“月下含栗”。
- 起始单元格保持零基第 23 行第 0 列。
- 48 帧依次占满第 23、24、25 行，每行 16 帧；图集尺寸继续保持 `3072 × 5408`，无需扩展。
- `frameCount` 从 36 改为 48，`frameDurations` 替换为本设计中的 48 项数组。
- `repeatCount=1`、`autoplayWeight=5`、`cooldownMs=90000`、`showInMenu=true` 保持不变。
- 旧 `tasteCake` 继续作为隐藏彩蛋素材保留，不恢复普通菜单、自主动作或动作展示入口。

## 8. 播放与中断

- 手动播放仍可随时触发；现有控制器会先停止闲逛并返回待机基准，再启动该动作。
- 自主动作只在闲置/允许注视的基础状态触发，因此新动作的首帧以待机为基准即可自然进入。
- 拖拽、切换宠物、播放其他动作和退出程序仍可立即中断，不增加不可取消的剧情播放模式。
- 动作自然结束后沿用现有 `manual_finished()` 和 `_resume_base_mode()` 返回待机；最后一帧必须与该切换视觉兼容。

## 9. 验收标准

### 9.1 自动验证

- 资源契约验证 `frameCount=48`、48 项时长总和为 9600 毫秒，并检查三行跨行坐标。
- 图集第 23–25 行的 48 个单元格均含有效 alpha；该区域之外的原有图集像素不得改变。
- 归档 WebP 在源码目录、冻结目录和安装包暂存目录中均存在，并保持 8,634,008 字节及上述 SHA256；活动图集与归档图集必须是两个独立文件。
- 测试动作在 9600 毫秒边界只完成一次，随后回到待机，不循环、不越界。
- 菜单、动作展示、约 `5/101` 的名义权重和 90 秒自动冷却继续有效；手动播放仍可绕过自动冷却。
- 第一帧和最后一帧分别与南宫婉待机首帧做像素/锚点复核；允许首尾相同，但禁止相邻运行帧完全重复。
- 在深色和浅色背景上合成相邻帧差异图；人物与屋檐有效 alpha 区域内，任一相邻帧的平均 RGB 差值不得超过 35，变化超过 20 灰度级的像素占比不得超过 35%。月辉亮度变化另行统计，不能用背景渐亮掩盖人物跳变。

### 9.2 动态人工验收

- 必须生成按 48 项真实时长播放的 GIF 或 MP4；静态接触表不能单独作为通过依据。
- 至少完整观看正常速度、75% 速度和 125% 速度三遍，重点检查站到坐、御物、含栗、起身和回待机五个接缝。
- 在宠物缩放 75%、100% 和 125% 下实际触发，确认人物不漂移、栗糕可辨认、紫光不糊成色块。
- 在深色和浅色桌面背景上各播放一次，确认透明边缘、月面和屋檐没有矩形底、白边或黑边。
- 从正常站立、看向鼠标、自动闲逛停止后三种入口播放，确认动作始终像同一个桌面人物连续完成。
- 人工动态预览未通过时不得打包、安装或发布，即使自动测试全部通过也不能视为完成。

## 10. 发布约束

- 本次重做完成后版本号应高于 2.4.1，并在更新日志中明确说明 2.4.1 的旧“月下含栗”已被连续桌面动作替换。
- 在动态预览得到用户确认之前，只允许生成本地候选资源和测试包，不更新本机正式安装，不推送 GitHub/Gitee Release。
- 2.4.1 安装包和历史标签继续保留，方便对比和回退。
